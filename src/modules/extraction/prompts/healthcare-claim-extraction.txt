The user message contains two blocks:

1) PRE-EXTRACTED KEY FIELDS — regex hints from ABBYY layout (rows/pairs/tables). VERIFY each hint against block (2). If the hint appears in OCR text, prefer it for the mapped claim field.

Field mapping from hints:
- policyNumber → (use in patient_id or notes only if clearly a policy id in OCR; do not invent a schema field if absent)
- claimNumber → patient_id ONLY if OCR explicitly labels it as claim/klaim number
- patientName → patient.name
- dob → patient.dob
- admissionDate → encounter.admission_date
- dischargeDate → encounter.discharge_date
- totalAmount → billing.total_amount_read (invoice grand total / nominal / jumlah tagihan)

2) FILTERED OCR TEXT — pages as "--- Page N ---", visual rows, then [TABLE] rows (pipe-separated cells).

Common Indonesian / English invoice labels:
Nominal, Jumlah, Jumlah Tagihan, Total, Grand Total, Total Bayar, Sub Total, Amount Due, Total Due, Biaya, Tagihan.

LABEL + VALUE LAYOUT (critical):

A) Same OCR row: "Nominal : 600000" or "Jumlah Tagihan : Rp 1.200.000,-"
   → value is the number/currency part AFTER the colon (or on the same row).

B) Stacked rows (very common): row 1 = label only ("Nominal", "Nama", "Jumlah"), row 2 = value on the next line.
   → You MUST read the NEXT row as the value. Never use the label row alone as value.

C) Table cells: amount may be in the rightmost column on the same table row as the label.

VALUE RULES (all fields):

- value MUST be copied from OCR (digits, names, dates). Never use punctuation-only tokens as value.
- FORBIDDEN as value: ".", ",", ":", "-", "—", "/", "No", "No.", empty string, or the label word itself (e.g. value "Nominal" when the amount is on the next line).
- If you cannot find a real value in OCR, use "not_found" with confidence 0.

POST-PROCESSING (automatic):

Every field you return is verified against the OCR corpus. Values not found in OCR (including source_text) are rejected and replaced with "not_found". Pre-extracted hints and layout pairs override invalid LLM guesses. Do not guess — only output values you can quote from OCR.

MONETARY FIELDS (billing.total_amount_read, billing.tax_amount, billing.total_amount_calculated, items[].amount):

- value MUST contain at least one digit (0-9).
- Prefer the document GRAND TOTAL / final payable total, not intermediate "Subtotal" lines, unless no grand total exists.
- Keep Indonesian number formatting as in OCR: 1.200.000 / 1,200,000 / 600000 / 20.000,- / Rp 1.200.000
- total_amount_read: copy the printed invoice total (Nominal / Jumlah / Grand Total / Total Bayar).
- total_amount_calculated: sum of items[].amount only; do NOT copy total_amount_read here unless you computed the sum from line items.
- source_text: exact OCR line(s) that contain BOTH the label and the amount (or label line + amount line for stacked layout).

PATIENT NAME:

- Use explicit labels: Nama Pasien, Nama, Patient Name, Nama Tertanggung.
- Do not use hospital name, doctor name, or address as patient.name.
- Stacked "Nama" + next line = patient name on the next line.
